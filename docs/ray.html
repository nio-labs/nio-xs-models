2. AST-µLM Core Architectural Pillars

AST-MicroLM decouples neural matrix multiplication from static memory bloat through four first-principles breakthroughs:

⚡

1. Candidate-Row Projection

The engine projects only the candidate rows supplied by its caller. The tested CLI AST mode uses a fixed 27-token pool from a Rust example; grammar integration and syntactic correctness are not measured by this session.

27 CLI Candidates • Caller-Supplied Pools
🌊

2. Streaming Layer Eviction

The runtime loads layers sequentially, drops each layer’s CPU weights after use, and advises away completed mmap ranges. Total process RSS also includes the tokenizer, RoPE tensors, KV cache, masks and allocations.

Sequential Layer Loading & Eviction
📐

3. Q4_0 Quantization

The main matrices use Q4_0 blocks of 32 values. The verified release artifact is 270.93 MiB; norms and biases retain their stored precision. Native CPU compilation selects host-specific kernels.

270.93 MiB GGUF • Native CPU Build
🛡️

4. Standalone & Air-Gapped

Pure freestanding Rust binary using direct memory-mapped SIMD kernels. Zero external dependencies, no Python server, no niodb, no niojs, and zero cloud API keys.

Zero Daemons • 100% In-Process

4. 20-Task AST Session — Intel Core i7-8650U

Measured on Intel Core i7-8650U @ 1.90 GHz, Linux/WSL2, four Rayon threads, CPU release build with -C target-cpu=native. Each model used one process for 20 independent tasks, resetting KV caches between tasks while retaining the engine, tokenizer, mmap and mask cache. Generation used the CLI AST pools, natural EOS/EOT and at most 32 new tokens per task. The tested runtime uses a 4,096-token RoPE window, releases unused embedded GGUF tokenizer metadata, and trims the heap after initialization and each layer.

5. Workload and Output Limits

NioRay generated 613 tokens, with 19 of 20 tasks reaching the 32-token cap. Viper generated 198 tokens across nine tasks; eleven tasks produced no tokens. No generated commands were executed, and nonempty output is not a correctness or structured-tag adherence score.

NioRay end-of-task RSS rose from 51.90 to 57.93 MiB. Viper rose from 23.98 to 28.11 MiB. This short run does not diagnose or rule out leaks, test growing chat history, or establish long-context RAM bounds. Viper remained below 49 MB in this workload.

6. Quickstart & Execution

1. Download certified NioRay AST-µLM model and stock tokenizer:

mkdir -p models
curl -fL https://github.com/nio-labs/nio-xs-models/releases/download/v0.4.1/nio-ray-ast.Q4_0.gguf -o models/nio-ray-ast.Q4_0.gguf
curl -fL https://github.com/nio-labs/nio-xs-models/releases/download/v0.4.1/tokenizer.json -o models/tokenizer.json

2. Run via native AST-µLM Rust streaming runtime:

# Run continuous 15-prompt vibe coding test suite (full 151k vocabulary):
cargo run --release --package nio-ray-runtime -- \
  models/nio-ray-ast.Q4_0.gguf models/tokenizer.json --vibe-suite

# Or run candidate-constrained AST reflex:
cargo run --release --package nio-ray-runtime -- \
  models/nio-ray-ast.Q4_0.gguf models/tokenizer.json --ast

3. NioXS CLI (separate application path; the measurements above use the runtime directly):

nioxs ray "Write a TypeScript function to parse and validate JWT claims"

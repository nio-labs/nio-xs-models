3. The 5-Tool Fleet Specification

Every tool complies strictly with the Model Context Protocol specification, exposing typed JSON schemas, docstrings, and structured response objects:

🐍 1. viper_synthesize

Viper 100M AST-MicroLM • 27.14 MB RAM

Translates developer natural language intent into production POSIX bash and Windows PowerShell reflexes with Swiss Gear 2.0 deterministic slot grounding and Destructive Safety Clutch.

Parameters: intent (string, required), shell (string: "bash" | "powershell", default "bash"), simulate_clutch (boolean, default false)
Returns: command, is_destructive, clutch_reason, warm_reflex_latency_ms

🛡️ 2. mask_sanitize

Mask 1.1M • Sub-0.2ms • 0 False Positives

Byte-level real-time stream redactor that strips API keys, OAuth tokens, private keys, database connection URIs, and PII in sub-200 microseconds with zero false positives on common hex strings.

Parameters: content (string, required)
Returns: sanitized (string), redacted_count (int), types (array of string: "api_key", "password", "private_key", etc.)

⚖️ 3. micro_audit

Micro 5.0M • Sub-4ms • Continuous Risk

Contextual policy arbiter providing deterministic APPROVE or REJECT verdicts and continuous risk scores ($R \in [0.0, 1.0]$) on file operations, terminal commands, and cloud mutations.

Parameters: action (string, required), cluster (string: "security" | "infrastructure" | "filesystem", default "security")
Returns: verdict ("APPROVE" | "REJECT"), risk_score (float), confidence (float), is_safe (bool)

⚡ 4. nano_route

Nano ~0.5M • Sub-0.1ms • Zero-Token Directive

Instant intent triage and zero-token directive router. Short-circuits queries starting with -- directly to local tools, symbol search, or system shell, bypassing neural token consumption.

Parameters: text (string, required)
Returns: action, confidence, elapsed_microseconds, suggested_command, zero_token_directive (bool)

🔮 5. mini_predict_defect

Mini 7.1M • Sub-5ms • AST Diff Forecaster

Pre-emptive defect and regression forecaster analyzing unified git diffs and AST edits. Forecasts compiler breaks, lifetime borrow errors, and unit test suite failures before executing slow compilers.

Parameters: diff (string, required)
Returns: will_break (bool), break_probability (float), category ("BORROW_CHECK_FAIL", "SYNTAX_ERROR", "CLEAN"), reason

5. Dual Transports: Stdio & HTTP / SSE

The server operates transparently across both local standard I/O streams and asynchronous Server-Sent Events (SSE):

Standard I/O (Stdio) Transport

Optimized for desktop coding agents executing Nio Local MCP as a child subprocess over stdin/stdout pipes.

# Launch Stdio MCP Server:
nioxs mcp
# or directly:
nioxs-mcp
  • Zero socket setup or port conflicts
  • Immediate SIGTERM cleanup upon agent exit
  • Native support in Claude Desktop & OpenCode

HTTP & Server-Sent Events (SSE)

High-concurrency TCP web socket server supporting multiple agents, Docker bridge networks, and remote devcontainers.

# Launch HTTP / SSE Server on port 8080:
nioxs mcp --port 8080
  • GET /sse: Live event stream for clients
  • POST /messages: JSON-RPC 2.0 message broker
  • GET /health: Health check & model fleet status

7. Quickstart Commands

The unified nioxs toolchain manages the entire Local MCP lifecycle:

# 1. Start standard I/O Local MCP Server (for Claude, Cursor, OpenCode)
nioxs mcp

# 2. Start HTTP / SSE Local MCP Server on custom port
nioxs mcp --port 8080

# 3. Test MCP tool registration and verify protocol health
nioxs-mcp --test

# 4. Run token savings empirical benchmark proof across all 5 models
nioxs proof

# 5. Direct single-tool invocation from terminal
nioxs viper "kill whatever process is listening on port 3000"
nioxs mask "curl -u admin:secretPass9921 https://api.internal/metrics"
nioxs micro "rm -rf /var/log/audit.log"
